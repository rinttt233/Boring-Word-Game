## 一、调研结论：同类项目教了什么

| 项目 | 关键设计 | 对本项目的映射 |
|---|---|---|
| [Captain of Industry 维修品](https://wiki.coigame.com/Maintenance) | 维护品 I/II/III 被**所有建筑与车辆持续消耗**；**空闲建筑仍消耗 33%**，仅"暂停"为 0；维护值 <75% 起有故障概率，0% 时约每月 50% 故障，故障恢复后**不自动回满** → 反复故障 | 我们只有"记忆加固"且未运转设施零成本；维护应做成随规模增长的持续消耗 |
| [Factorio 石油加工](https://wiki.factorio.com/Oil_processing) | 多产物联动：**任一产物满则整机停产**；裂解把多余产物转成所需（最优比 20:5:17）；"只想要重油"可用只产重油的液化配方 | 我们副产物无上限直接入库 → 缺"必须找出口"的决策；应加积压惩罚 + 转化/放空出口 |
| [ONI 热管理](https://gamefoundry.games/blog/oxygen-not-included-heat-management-cooling-guide) | 压力是**延迟账单**；应对顺序：停可避免的运行 → 隔离 → 缓冲 → 搬运 → 彻底消灭；"临时覆盖"必然变中期危机 | 我们的沙暴/夜晚/劣化都是瞬时倍率，缺"缓冲层"与"预警" |
| [Factorio FFF-408 统计](https://factorio.com/blog/post/fff-408) | 累加器**电量时间线**、**按表面**统计、**按品质**统计、特殊"最终总量"条目 | 电力页只有瞬时预算、物料页只有当前净额 → 缺时间线/分解/终局计量 |
| [Aven Colony 生产上限讨论](https://steamcommunity.com/app/484900/discussions/0/1471966894872371382)、[Songs of Syx 维护讨论](https://steamcommunity.com/app/1162750/discussions/0/594018749968922110) | 共识：**无限仓库 + 无维护 ⇒ 后期只剩排队，压力消失** | 正是本项目当前中后期的状态 |

## 二、用户决策记录（本轮定稿）

| 问题 | 决定 |
|---|---|
| 1. 单元扩张的机制 | **效率科技**（单元数量保持稀缺，靠"单元效能"提升单单元覆盖能力） |

| 5. 文档授权 | **确认**：本文档 + `docs/roadmap.md` + `TODO.md` 登记 |

## 三、A 组：平衡性调整

| # | 现状（已核对代码） | 建议 | 决策 | 批次 |
|---|---|---|---|---|
| A1 | `degrade_per_sec=0.02` → 100 到 0 约 83 min；`maintain` 20 电+5 合金+8s+1 单元恢复 25（≈抵 21 min） | 劣化随规模增长：`degrade = base + k×固化条目数`；加固恢复量按完整度分档递减 | ✅ 已实施（批次2） | 2 |
| A2 | `industry.tick` 中 `if not f.assigned: continue` → 未运转设施零成本 | 待机消耗（未分配仍吃 33%，封存才是 0 且重启需时间+单元） | ✅ 已实施（批次2） | 2 |
| A3 | 副产物 `economy.add` 无上限 | 积压惩罚（超阈值降速/停摆）+ 多手段应对 | ✅ 采纳 | 3 |
| A4 | `_consume` 按可用比例 → 缺电时全厂一起半速 | 电力优先级分层 + 低电自动降载 | ✅ 采纳 | 4 |
| A5 | 单元来源仅开局 3 + 残骸；`core/units.py` 注释预留"效率"但未实现 | 由"效率科技"路线实现（见 C1/B3） | ✅ 已实施（批次1） | 1 |
| A6 | `salvager` 免建造费、拆完直接 +1 单元；外圈残骸率反而更高（32%） | 残骸产出改为"合金 + 部件"，单元需经加工链 | ✅ 采纳 | 5 |

| A8 | 环境事件纯倍率、无预警无缓冲 | 事件预警时间线（提前提示）+ 加固设施 | ✅ 采纳 | 6 |
| A9 | 60 物质/43 设施/35 配方/23 条目的成本手工设定 | 成本换算表脚本：折算"设施·秒 + 单元·秒"，校验曲线单调 | ✅ 已实施（批次0） | 0 |
| A10 | 胜利仅考"恢复 + 建造完成" | 结算统计与评级（用时/停摆/单元峰值/记忆均值） | ✅ 采纳 | 8 |
| A11 | `build_time` 仅展示；昼夜 60s 与"21 min 一次加固"节奏不匹配 | **已定：建造耗时作业**（占执行单元 N 秒，"建造中"状态） | ✅ 已实施（批次1.5） | 1.5 |

## 七、E 组：明确不做

| 项 | 原因 |
|---|---|
| 敌人 / 战斗 | 主题是"孤独的受损 ASI"，对抗会稀释记忆压力主线 |
| 无限科技树 / 无限资源 | 会摧毁"记忆劣化 + 单元稀缺"两个核心压力 |
| 默认仓库上限与复杂物流 | 偏离"执行单元调度"这一核心瓶颈（只适合做难度选项，而本轮不做难度模式） |
| 随机刷新地块内容 | 稀释"勘探选址"的决策价值 |
| 副产物"市场/出售"出口 | 无敌人无经济体系，超出设定 |
